# 一、同步 / 异步 vs 阻塞 / 非阻塞
（bit 是操作系统 / 网卡底层的事，应用层看不到）

| 你用过的             | Java 传统 BIO   | Netty 底层 IO      |
| ---------------- | ------------- | ---------------- |
| `BitInputStream` | `InputStream` | **ByteBuf**      |
| 按 bit 读          | 按 byte 阻塞读    | 按 byte 非阻塞读      |
| 自定义 bit 流        | JDK 原生字节流     | Netty 自研高性能字节缓冲区 |
| 有流的开闭、顺序读        | 单向流、阻塞        | 随机读写、零拷贝、自动扩容    |
## 二、Java IO 演进路线（从慢到快）

**在当前 Java 生态中，NIO 是绝对的主流选择**，尤其在 Linux 服务器环境和高并发网络编程领域。虽然 AIO 理论上性能更优，但因**Linux 支持不完善**、**调试复杂**和**生态薄弱**，实际应用远少于 NIO。

### 2.1 BIO（同步阻塞 IO）：一连接一线程

- **原理**：每个客户端连接，服务器都开一个独立线程处理读写
- **问题**：1000 个连接就要 1000 个线程，线程切换开销大，高并发直接崩溃
- **适用**：连接数 < 100 的简单场景，比如内部工具

### 2.2 NIO（同步非阻塞 IO）：一线程管千连接

JDK 1.4 引入，核心是「**Channel（通道）+ Buffer（缓冲区）+ Selector（选择器）**」三剑客，一个线程就能管理成千上万的连接，是目前 Java 网络编程的主流。

### 2.3 AIO（异步非阻塞 IO）：操作系统帮你干活

JDK 7 引入（又称 NIO. 2），真正的异步：你发起 IO 请求后直接返回，操作系统完成读写后主动通过回调通知你。但底层依赖操作系统支持，Linux 上实现不好，几乎没人用。
为什么 AIO 几乎没人用？

1. **Linux 支持差**：Linux 内核没有真正的异步 IO，Java AIO 在 Linux 上是用 epoll 模拟的，性能不如优化后的 NIO
2. **Windows 支持好**：Windows 上用 IOCP 实现，但服务器几乎都是 Linux
3. **编程复杂**：回调嵌套严重，代码可读性差，调试困难
4. **生态差**：没有成熟的框架，Netty 也放弃了对 AIO 的支持
