### 🗺️ 第一步：先看森林（整体架构）
Java 集合主要分为两大阵营（记住这张图的逻辑）：
1.  **Collection (单身汉阵营)**：单个元素的集合。
    *   **List (有序列表)**：像排队，有先后顺序，可重复。
    *   **Set (独一无二集)**：像抽奖箱，元素无序，不可重复。
    *   **Queue (队列)**：像银行排队，先进先出 (FIFO)。
2.  **Map (情侣档阵营)**：键值对 (Key-Value) 的集合。
    *   像字典，通过 Key (页码) 找 Value (内容)。

### 一、Collection 接口（所有单身汉的老大）
Collection 是 List、Set、Queue 的父接口，它定义了所有单列集合都必须具备的**基本操作**。

#### 1. 常用 API 解析（先记这几个最核心的）
```java
Collection<String> coll = new ArrayList<>(); // 多态写法

// 增
coll.add("张三");           // 添加单个元素
coll.addAll(另一个集合);    // 把另一个集合的所有元素加进来

// 删
coll.remove("张三");        // 删除指定元素
coll.clear();               // 清空集合

// 查
int size = coll.size();     // 集合长度
boolean isEmpty = coll.isEmpty(); // 是否为空
boolean contains = coll.contains("张三"); // 是否包含某个元素

// 变数组
Object[] array = coll.toArray(); // 把集合变成数组
```

#### 2. Iterator 接口（遍历集合的专业户）
在 Java 中，遍历集合统一使用**迭代器 (Iterator)**。这就像一个“导游”，带你一个一个游览集合里的元素。

**核心方法：**
*   `hasNext()`: 问导游“后面还有人吗？”
*   `next()`: 让导游“把下一个人带过来”。

**代码示例：**
```java
Collection<String> list = new ArrayList<>();
list.add("A");
list.add("B");
list.add("C");

// 获取迭代器对象
Iterator<String> it = list.iterator();

// 开始遍历
while (it.hasNext()) {
    String element = it.next();
    System.out.println(element);
}
```

#### 3. ArrayList 的 iterator () 方法源码（JDK 1.8）
这里先不贴大段源码吓你，只需要知道：
ArrayList 内部有一个**内部类 Itr**，实现了 Iterator 接口。
它通过一个 `cursor`（游标）变量来记录当前遍历到的位置。

#### 4. 集合之间如何比较
集合之间的比较主要看**内容**。
*   `equals()`: 比较两个集合的元素是否完全一样（顺序和内容）。
*   `containsAll()`: 看 A 集合是否包含 B 集合的所有元素（判断子集）。

### 二、List 接口（有序的队列）
List 最大的特点是：**有序**（有索引下标）、**可重复**。
它像一个数组，但是长度可以**自动变长**。

#### 5. 常用 API 解析（比 Collection 多了“索引操作”）
```java
List<String> list = new ArrayList<>();

// 增（在指定索引位置插队）
list.add(0, "李四"); 

// 删（删除指定索引的元素）
list.remove(0);

// 改（修改指定索引的元素）
list.set(0, "王五");

// 查（获取指定索引的元素）
String s = list.get(0); 
```

#### 6. ArrayList 源码（JDK 1.8）【重点】
**底层原理：** 就是一个**数组**。
**核心机制：** **扩容机制**。

*   **初始化：** 当你 `new ArrayList<>()` 时，默认是一个空数组。
*   **第一次 add：** 数组长度扩容为 **10**。
*   **后续扩容：** 当数组满了，会自动扩容为原来的 **1.5 倍**。
    *   (int newCapacity = oldCapacity + (oldCapacity >> 1);)
*   **缺点：** 由于是数组，在中间**插入/删除**元素时，后面的元素都要移动，效率低。
*   **优点：** **查询**快（通过索引直接定位）。

#### 7. Vector 源码（JDK 1.8）
Vector 和 ArrayList 几乎一模一样，底层也是数组。
**唯一区别：**
*   **Vector** 是**线程安全**的（方法上加了 `synchronized`），但效率低，现在很少用了。
*   **ArrayList** 是**线程不安全**的，但效率高。

#### 8. Iterator () 方法的 Itr 迭代器并发修改异常
这是一个经典异常：`ConcurrentModificationException`。

**场景：** 你在用迭代器遍历集合时，同时用集合的 `add/remove` 方法修改了集合。
**原理：** 迭代器内部有个计数器 `modCount`，如果集合被修改了，对不上号就报错。
**解决：** 遍历的时候如果要删除，用**迭代器自己的** `remove()` 方法。

#### 9. ListIterator 接口
List 独有的迭代器，比普通 Iterator 更牛：
*   它不仅可以**向后**遍历 (`next`)，还可以**向前**遍历 (`previous`)。
*   它还可以在遍历的时候**修改**和**添加**元素。

### 三、LinkedList 实现类（链表结构）
#### 10. 常用 API 解析
LinkedList 不仅实现了 List 接口，还实现了 Deque（双端队列）接口。所以它既能当 List 用，也能当**队列**或**栈**用。
```java
LinkedList<String> ll = new LinkedList<>();
ll.addFirst("头"); // 头部添加
ll.addLast("尾");  // 尾部添加
String first = ll.getFirst(); // 获取头部
```

#### 11. 两种迭代器使用方法比较
*   **Iterator:** 单向，从前往后。
*   **ListIterator:** 双向，可前可后，还能改。

#### 12. LinkedList 源码（JDK 1.8）【重点】
**底层原理：** **双向链表**。
*   每个元素（节点）不仅存着数据，还存着**前一个节点**和**后一个节点**的地址。
*   **优点：** 在中间**插入/删除**元素时，不需要移动大量元素，只需要改变前后节点的指向，效率高。
*   **缺点：** **查询**慢（没有索引，每次都要从头开始找）。

> **小结：** 查询多用 ArrayList，增删多用 LinkedList。

### 四、Set 接口（独一无二的集合）
Set 最大的特点：**元素不可重复**。

#### 13. HashSet 实现类和源码（JDK 1.8）【重点】
**特点：** 无序，无索引，元素不可重复。
**底层原理：** 其实就是个**HashMap**（存到 Map 的 Key 里）。
**如何保证不重复？**
1.  先比较元素的 **hashCode** 值。
2.  如果 hashCode 一样，再调用 **equals** 比较。
3.  只有两者都一样，才认为是重复元素，不存。

#### 14. LinkedHashSet 实现类和源码
**特点：** 有序（怎么存的，怎么取出来）。
**底层原理：** 继承自 HashSet，但是内部多了一条**链表**来记录插入顺序。

#### 15. TreeSet 实现类和源码
**特点：** 可排序（默认自然排序，如数字从小到大）。
**底层原理：** 基于**红黑树**（一种自平衡二叉树）。
**两种排序方式：**
1.  **自然排序：** 让元素类实现 `Comparable` 接口。
2.  **比较器排序：** 在创建 TreeSet 时传入 `Comparator` 对象。

### 五、Map 接口（键值对夫妻档）
Map 存的是 `<Key, Value>` 一对数据。Key 不能重复，Value 可以重复。

#### 16. 常用 API 解析
```java
Map<String, Integer> map = new HashMap<>();

// 增（改）：如果 Key 不存在就新增，存在就覆盖旧值
map.put("张三", 18);

// 删
map.remove("张三");

// 查
Integer age = map.get("张三"); // 根据 Key 找 Value
boolean b = map.containsKey("张三"); // 判断 Key 是否存在
```

#### 17. HashMap 源码（JDK 1.8）【重中之重】
这是面试必问！
**底层结构：** **数组 + 链表 + 红黑树**。
*   **数组：** 叫哈希桶 (Bucket)，默认长度 16。
*   **链表/红黑树：** 当多个 Key 的 hash 值算出的数组下标一样时（哈希碰撞），它们会在该位置形成链表。
    *   当链表长度 > **8** 且数组长度 > **64** 时，链表会转为**红黑树**（提高查询效率）。
    *   当红黑树节点 < **6** 时，又会变回链表。
**加载因子 (Load Factor):** 默认 0.75。
*   意思是数组存满 75% 时（16 * 0.75 = 12），数组就会**扩容**为原来的 2 倍。

#### 18. TreeMap 源码
和 TreeSet 类似，底层也是红黑树，Key 会自动排序。

### 六、同步类容器（旧的线程安全方案）
#### 19. Collections 工具类转换
Collections 是一个工具类（像 Arrays 一样）。
它可以把线程不安全的集合变成线程安全的：
```java
List<String> list = new ArrayList<>();
// 变成线程安全的 List
List<String> synchronizedList = Collections.synchronizedList(list);
```
**原理：** 其实就是在原有的方法外包了一层 `synchronized` 代码块。

#### 20. Collections 源码
主要是一些静态工具方法，如 `sort`（排序）、`reverse`（反转）、`shuffle`（打乱）等。

### 七、并发类容器（Java 5 后的高性能方案）
上面的同步容器效率低，因为它锁住了整个集合。并发容器用了**锁分段**等技术，效率更高。

#### 21. ConcurrentMap
最常用的是 `ConcurrentHashMap`。
**原理（JDK 1.8）：** CAS + synchronized。不再是锁住整个 Map，而是锁住数组的某一个节点（链表头或红黑树根）。并发性能极大提升。

#### 22. COW (Copy On Write) 写时复制容器
这是一种很乐观的策略：**读时完全不加锁，写时复制一份新的修改。**

1.  **CopyOnWriteArrayList**
    *   替代线程安全的 Vector。
    *   **原理：** 当你往里面 add 元素时，它会把底层数组复制一份，在新数组里加，加完再把引用指向新数组。
    *   **场景：** 读多写少（因为写操作很耗内存）。

### 八、队列（Queue）
队列通常用于**生产者-消费者**模式。

#### 23. BlockingQueue 接口常用 API
这是**阻塞队列**。
*   **如果队列满了，生产者线程会阻塞，直到有空位。**
*   **如果队列空了，消费者线程会阻塞，直到有新元素。**

#### 24 - 29. 各种队列实现类
*   **ArrayBlockingQueue:** 基于**数组**的有界阻塞队列。
*   **LinkedBlockingQueue:** 基于**链表**的阻塞队列（默认大小 Integer. MAX_VALUE，相当于无界）。
*   **SynchronousQueue:** 不存储元素的队列。生产一个必须消费一个，不然生产不了。
*   **PriorityQueue:** 优先级队列（内部排序，不是先进先出）。
*   **DelayQueue:** 延迟队列（只有时间到了，才能取出元素）。
*   **Deque:** 双端队列（两头都可以进和出）。
