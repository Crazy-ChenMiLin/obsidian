# 数组
```
## 四、关键对比总结
表格

|问题场景|数组的缺陷|集合的解决方案|
|---|---|---|
|**动态增删元素**|需手动扩容/移动数据，代码冗余|自动扩容，`add()`/`remove()` 直接操作|
|**唯一性校验（如姓名）**|需 O(n) 循环检查重复|`Set` 通过哈希表 **O(1) 完成去重**|
|**结构化对象操作**|无内置方法，需硬编码遍历逻辑|支持 Stream API 实现 **声明式操作**|
|**空指针与越界风险**|高频易错点（需手动校验索引）|内部封装边界检查，**显著降低错误率**|

**实际开发中，阿里巴巴《Java开发手册》明确要求**：

> “**业务场景优先使用集合而非数组**。数组仅用于性能敏感或长度固定的底层场景。”  
> 若强行用数组实现动态数据管理，将导致代码膨胀、可读性下降，且难以通过代码审查。
```
