# 注解简答题

## 简答题

### 1. 请简述什么是注解，以及注解的主要作用。

参考答案：
- 注解是 Java 5 引入的一种语法糖，是代码中的特殊标记
- 注解用于为代码提供元数据，不直接影响代码执行
- 主要作用：
  - 编译检查（如 @Override、@Deprecated）
  - 框架配置（如 Spring、MyBatis 注解）
  - 文档生成（如 @Documented）
  - 运行时处理（通过反射获取注解信息）

### 2. 请解释 @Retention 和 @Target 元注解的作用，并说明常见的保留策略和目标类型。

参考答案：
- @Retention：指定注解的保留阶段
  - SOURCE：只在源码中保留，编译时丢弃
  - CLASS（默认）：保留到编译时，运行时丢弃
  - RUNTIME：一直保留到运行时，可通过反射获取

- @Target：指定注解可以应用的位置
  - TYPE：类、接口、枚举
  - METHOD：方法
  - FIELD：字段
  - CONSTRUCTOR：构造方法
  - PARAMETER：方法参数
  - ANNOTATION_TYPE：注解类型

### 3. 请简述如何通过反射获取注解信息。

参考答案：
- 获取 Class 对象：Class.forName()、类名.class、对象.getClass()
- 获取类上注解：clazz.getAnnotation(注解类名.class)
- 获取方法上注解：method.getAnnotation(注解类名.class)
- 获取字段上注解：field.getAnnotation(注解类名.class)
- 判断是否存在注解：isAnnotationPresent(注解类名.class)
- 注意：只能获取 RUNTIME 保留策略的注解

### 4. 请简述 @Component、@Service、@Repository、@Controller 注解的区别。

参考答案：
- @Component：通用组件注解，Spring 会自动扫描并注册为 Bean
- @Service：业务逻辑层组件，本质上与 @Component 相同，但语义更明确
- @Repository：数据访问层组件，除了自动注册，还会激活异常转换
- @Controller：控制器层组件，用于 Spring MVC

### 5. 请解释什么是元注解，并列举常见的元注解及其作用。

参考答案：
- 元注解是用来注解其他注解的注解
- 常见元注解：
  - @Retention：指定注解的保留阶段
  - @Target：指定注解可以应用的位置
  - @Documented：表示注解会被包含在 JavaDoc 中
  - @Inherited：表示子类会继承父类的注解

### 6. 请简述 Lombok 中 @Data 注解的作用，以及使用 Lombok 的优缺点。

参考答案：
- @Data 注解会自动生成：
  - 所有字段的 getter 和 setter
  - toString() 方法
  - equals() 和 hashCode() 方法
  - 无参构造方法（如果没有任何构造方法）

- 优点：简化代码，减少样板代码
- 缺点：
  - 增加了学习成本
  - 可能会影响代码可读性
  - 调试时不易追踪
  - 某些 IDE 可能不支持

### 7. 请解释 @Autowired 和 @Resource 注解的区别。

参考答案：
- @Autowired：
  - Spring 提供的注解
  - 按类型进行自动装配
  - 可以配合 @Qualifier 按名称指定
  - 默认 required = true

- @Resource：
  - JavaEE 标准注解（JSR-250）
  - 默认按名称进行装配
  - 可以指定 name 属性按名称
  - 没有 type 属性

### 8. 请简述 @PathVariable 和 @RequestParam 的区别。

参考答案：
- @PathVariable：用于获取 URL 路径中的参数
  - 示例：@GetMapping("/user/{id}")
  - 获取 /user/123 中的 123

- @RequestParam：用于获取 URL 查询参数
  - 示例：@GetMapping("/user/search?name=zs")
  - 获取 ?name=zs 中的 zs

### 9. 请解释什么是函数式接口，以及 @FunctionalInterface 注解的作用。

参考答案：
- 函数式接口：只有一个抽象方法的接口（可以有多个 default 或 static 方法）
- 作用：
  - 编译时检查接口是否符合函数式接口定义
  - 如果接口不符合定义，编译器会报错
  - 使代码更清晰，明确接口的用途
  - 支持 Lambda 表达式

### 10. 请简述自定义注解的实现步骤。

参考答案：
1. 使用 @interface 定义注解
2. 使用元注解 @Retention 指定保留策略（通常为 RUNTIME）
3. 使用元注解 @Target 指定应用位置
4. 定义注解属性（如果有）
5. 在代码中使用注解
6. 通过反射获取注解信息并处理业务逻辑
