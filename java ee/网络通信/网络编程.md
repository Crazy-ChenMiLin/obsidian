### 一、3 个基础概念: IP 端口号 协议

1. **IP 地址**：设备在网络中的 “门牌号”，比如 `192.168.1.1`（局域网）或 `223.5.5.5`（公网），靠它找到对方设备。
2. **端口号**：设备上程序的 “房间号”，范围 0-65535，比如微信用某个端口、浏览器用另一个端口，靠它把数据送到具体程序。
3. **协议**：设备间通信的 “语言规则”，比如 TCP（可靠传输）、UDP（快速传输），约定好怎么发、怎么收、出错怎么办。

# TCP 协议：像 “打电话” 一样可靠

TCP 是**面向连接、可靠传输**的协议，核心是 “三次握手建连接，四次挥手断连接”，保证数据不丢、顺序不乱。

#### （1）三次握手（建立连接）

想象你给朋友打电话：

1. **你**：“喂，能听到吗？”（SYN 包）
2. **朋友**：“能听到，你呢？”（SYN+ACK 包）
3. **你**：“我也能听到，开始说话吧！”（ACK 包）

**为什么是三次？** 防止 “已失效的连接请求” 突然传到服务器，浪费资源。

#### （2）四次挥手（断开连接）

还是打电话的例子：

1. **你**：“我说完了，挂了啊？”（FIN 包）
2. **朋友**：“好的，等我说完最后一句。”（ACK 包）
3. **朋友**：“我也说完了，挂吧。”（FIN 包）
4. **你**：“好的，拜拜！”（ACK 包）

**为什么是四次？** 因为 TCP 是全双工的（双方都能发数据），断开时需要分别关闭 “发送通道” 和 “接收通道”。

#### （3）TCP 的可靠性机制

- **确认重传**：发出去的数据等对方确认，超时就重发。
- **流量控制**：通过滑动窗口控制发送速度，防止对方收不下。
- **拥塞控制**：根据网络拥堵情况调整发送速度，避免堵死网络。



## 六、粘包与拆包

### 6.1 什么是粘包 / 拆包？

TCP 是**面向流**的协议，数据像水流一样连续传输，没有 “边界”。比如：

- 客户端发了两次 “Hello”，服务器可能一次收到 “HelloHello”（**粘包**）
- 客户端发了一次 “HelloWorld”，服务器可能分两次收到 “Hello” 和 “World”（**拆包**）

### 6.2 解决方案

常用三种方法，推荐用 **“消息头 + 消息体”**：

1. **固定长度**：每条消息固定 100 字节，不够补空格（浪费空间）
2. **分隔符**：用 `\r\n` 或特殊符号分隔（如果消息里有分隔符就麻烦）
3. **消息头 + 消息体**：消息头里存消息体的长度（比如前 4 个字节是长度，后面是内容）

**代码示例（消息头 + 消息体）**：

``` python
import socket
import struct

def send_msg(client_socket, msg):
    # 1. 计算消息长度
    msg_len = len(msg)
    # 2. 把长度打包成4字节的二进制（struct.pack('!I', ...)，!是网络字节序，I是无符号整数）
    header = struct.pack('!I', msg_len)
    # 3. 先发头，再发消息体
    client_socket.send(header)
    client_socket.send(msg.encode('utf-8'))

def recv_msg(client_socket):
    # 1. 先收4字节的消息头
    header = client_socket.recv(4)
    if not header:
        return None
    # 2. 解包出消息长度
    msg_len = struct.unpack('!I', header)[0]
    # 3. 收指定长度的消息体
    msg = client_socket.recv(msg_len).decode('utf-8')
    return msg
```
