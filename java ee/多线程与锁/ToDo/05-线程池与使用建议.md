---
title: 线程池与使用建议
tags: [线程池, ThreadPoolExecutor, 并发]

---

为什么使用线程池：

- 避免频繁创建/销毁线程的开销
- 控制并发数量、管理任务队列和拒绝策略

常用类：ThreadPoolExecutor、ScheduledThreadPoolExecutor、Executors（工厂方法）

示例配置（生产建议明确使用 ThreadPoolExecutor 而非 Executors 的部分工厂方法）：

```java
ExecutorService pool = new ThreadPoolExecutor(
    4, // corePoolSize
    20, // maximumPoolSize
    60L, TimeUnit.SECONDS, // keepAlive
    new LinkedBlockingQueue<>(1000), // workQueue
    Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.AbortPolicy() // 拒绝策略
);
```

关键参数说明：

- corePoolSize：核心线程数。
- maximumPoolSize：最大线程数。
- keepAliveTime：超出核心线程数的线程空闲回收时间。
- workQueue：任务队列（SynchronousQueue、LinkedBlockingQueue、有界/无界等）。
- RejectedExecutionHandler：拒绝策略（Abort、CallerRuns 等）。

线程数估算：

- CPU 密集型：N_threads ≈ N_cpu + 1
- IO 密集型：N_threads = N_cpu * (1 + wait_time / compute_time)，仅为估算，需基于实际负载调优

优雅关闭：

```java
pool.shutdown();
if (!pool.awaitTermination(10, TimeUnit.SECONDS)) {
    pool.shutdownNow();
}
```

常见坑：

- Executors.newFixedThreadPool 使用无界队列，可能导致 OOM 或任务积压；生产中应慎用默认工厂方法。
- 错误配置 corePoolSize 与 queue 组合会使 maximumPoolSize 失效（例如使用无界队列时，maximumPoolSize 不会起作用）。
