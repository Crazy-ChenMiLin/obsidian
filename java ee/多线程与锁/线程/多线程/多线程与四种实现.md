### [有了进程为什么还需要线程?](#有了进程为什么还需要线程)

- 进程切换是一个开销很大的操作，线程切换的成本较低。
- 线程更轻量，一个进程可以创建多个线程。
- 多个线程可以并发处理不同的任务，更有效地利用了多处理器和多核计算机。
- 而进程只能在一个时间干一件事，如果在执行过程中遇到阻塞问题比如 IO 阻塞就会挂起直到结果返回。
- 同一进程内的线程共享内存和文件，因此它们之间相互通信无须调用内核。
### [为什么要使用多线程?](https://javaguide.cn/cs-basics/operating-system/operating-system-basic-questions-01.html#为什么要使用多线程)
**多核时代**: 多核时代多线程主要是为了提高进程利用多核 CPU 的能力。举个例子：假如我们要计算一个复杂的任务，我们只用一个线程的话，不论系统有几个 CPU 核心，都只会有一个 CPU 核心被利用到。
而创建多个线程，这些线程可以被映射到底层多个 CPU 上执行，在任务中的多个线程没有资源竞争的情况下，任务执行的效率会有显著性的提高，约等于（单核时执行时间/CPU 核心数）。



# 使用多线程技术

## 总结：
### 1. 永远优先用 Runnable/Callable，不要直接继承 Thread

- 继承 Thread 会占用唯一的继承机会
- Runnable/Callable 解耦了任务和线程，同一个任务可以被多个线程执行
- 线程池只能接收 Runnable/Callable，不能直接接收 Thread

### 2. 不要调用 `run()` 方法，要调用 `start()` 方法

- `thread.run()`：只是普通的方法调用，在当前主线程中执行，不会开新线程
- `thread.start()`：会启动一个新的线程，由 JVM 调用 `run()` 方法

### 3. 什么时候用哪个？

- 不需要返回结果：用 Runnable（比如异步打印日志、发送消息）
- 需要返回结果：用 Callable（比如异步计算、调用第三方接口获取数据）
- 线程池场景：两个都可以，线程池会自动把任务包装成线程执行

## 如何使用

### 1. 方式 1：继承 Thread 类（不推荐）

缺点：Java 单继承，继承了 Thread 就不能继承其他类了，任务和线程耦合

```
// 定义一个线程类，继承Thread
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("继承Thread的线程在运行：" + Thread.currentThread().getName());
    }
}

// 启动
public class Test {
    public static void main(String[] args) {
        MyThread thread = new MyThread();
        thread.start(); // 启动新线程
    }
}
```

### 2. 方式 2：实现 Runnable 接口（推荐，无返回值）

优点：解耦任务和线程，支持多继承，方便线程池管理

```
// 定义一个任务，实现Runnable
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("实现Runnable的任务在运行：" + Thread.currentThread().getName());
    }
}

// 启动
public class Test {
    public static void main(String[] args) {
        // 1. 创建任务
        MyRunnable task = new MyRunnable();
        // 2. 把任务交给Thread执行
        new Thread(task).start();
        // 3. 同一个任务可以交给多个线程执行
        new Thread(task).start();
    }
}
```

### 3. 方式 3：实现 Callable 接口（推荐，有返回值）

必须配合线程池和 `Future` 使用，不能直接交给 Thread

```
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

// 定义一个有返回值的任务，实现Callable
class MyCallable implements Callable<Integer> {
    private int a;
    private int b;

    public MyCallable(int a, int b) {
        this.a = a;
        this.b = b;
    }

    @Override
    public Integer call() throws Exception {
        // 可以抛出受检异常
        if (b == 0) {
            throw new ArithmeticException("除数不能为0");
        }
        // 返回计算结果
        return a / b;
    }
}

// 执行
public class Test {
    public static void main(String[] args) throws Exception {
        // 1. 创建线程池
        ExecutorService executor = Executors.newSingleThreadExecutor();
        // 2. 提交任务，得到Future对象
        Future<Integer> future = executor.submit(new MyCallable(10, 2));
        // 3. 获取结果（会阻塞，直到任务执行完成）
        Integer result = future.get();
        System.out.println("计算结果：" + result); // 输出：5
        // 4. 关闭线程池
        executor.shutdown();
    }
}
```

## 源码

### 1. Java 实现多线程有 3 种方法：Thread、Runnable、Callable 是错的。
####  Java 创建**新线程**，本质只有**唯一一种方式**

### `new Thread().start();`

- **Runnable 不是线程**，只是一个**任务接口**
- **Callable 也不是线程**，只是一个**带返回值的任务接口**
- 它们都**不能自己开线程**，最后必须交给 `Thread` 去执行

### 2. 那 Thread 为什么要 **implements Runnable**？

我们直接看 **JDK 源码**，一眼就懂：

```
public class Thread implements Runnable {  // 这里实现了 Runnable

    private Runnable target;

    // 构造方法可以传入一个 Runnable
    public Thread(Runnable target) {
        this.target = target;
    }

    // 重点！Thread 重写了 run() 方法
    @Override
    public void run() {
        if (target != null) {
            target.run();  // 如果传了 Runnable，就执行它的 run
        }
        // 没传的话，就执行 Thread 自己的 run（空的，需要你重写）
    }
}
```

### 原因：

### ① 统一规范：线程要执行的逻辑，统一用 `run()` 定义

`Runnable` 接口只有一个方法：

```
public abstract void run();
```

它的作用就是：**规定「线程要跑的代码放在哪里」**

`Thread` 作为线程类，必须遵守这个规范，所以必须 `implements Runnable`。

### ② 支持两种写法

Thread 实现 Runnable 后，就同时支持两种用法：

1. **继承 Thread，重写 run ()**
2. **传入 Runnable，执行外部任务**

这就是设计上的**灵活性**。

### ③ 让 JVM 统一调用

JVM 启动线程后，**只会调用 `run()` 方法**

不管你是 Thread 自己，还是外部 Runnable，接口统一，JVM 不用区别对待。
