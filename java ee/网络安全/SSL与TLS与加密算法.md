## 网络安全（SSL/TLS + 加密算法）

所有的网络通信都是不安全的，数据在传输过程中可能被**窃听、篡改、伪造**。SSL/TLS 就是解决这些问题的标准协议。

### 一、网络安全四大核心目标

1. **机密性**：数据只能被通信双方看到，不能被第三方窃听
2. **完整性**：数据在传输过程中没有被篡改
3. **身份认证**：确认对方是你要通信的人，不是冒充的
4. **不可否认性**：发送方不能否认自己发送过数据

### 二、加密算法基础

SSL/TLS 是多种加密算法的组合使用，先搞懂三种基础加密算法。

#### 1. 对称加密

- **原理**：加密和解密用**同一个密钥**
- **优点**：速度极快，适合加密大量数据
- **缺点**：密钥分发困难（怎么安全地把密钥发给对方）
- **常用算法**：AES（推荐）、DES（不安全）、3 DES（过时）

#### 2. 非对称加密

- **原理**：有一对密钥：**公钥（公开）** 和 **私钥（保密）**
    
    - 公钥加密的数据，只能用对应的私钥解密
    - 私钥加密的数据，只能用对应的公钥解密
    
- **优点**：解决了密钥分发问题
- **缺点**：速度极慢，不适合加密大量数据
- **常用算法**：RSA、ECC（椭圆曲线，性能更好）

#### 3. 哈希算法

- **原理**：将任意长度的数据转换为固定长度的摘要，**不可逆**
- **特点**：输入相同，输出一定相同；输入不同，输出几乎一定不同
- **作用**：验证数据的完整性
- **常用算法**：SHA-256（推荐）、SHA-512、MD 5（不安全）

#### 4. 数字签名

- **原理**：私钥加密哈希值 → 公钥解密验证
- **作用**：同时实现**身份认证**和**不可否认性**
- **流程**：
    
    1. 发送方计算数据的哈希值
    2. 用自己的私钥加密哈希值，得到数字签名
    3. 将数据和数字签名一起发给接收方
    4. 接收方用发送方的公钥解密数字签名，得到哈希值
    5. 接收方计算数据的哈希值，和解密得到的哈希值对比，如果相同则验证通过
    

### 三、SSL/TLS 协议详解

SSL（Secure Sockets Layer）是 TLS（Transport Layer Security）的前身，现在常用的是**TLS 1.2**和**TLS 1.3**（TLS 1.0/1.1 已被废弃）。

#### 1. TLS 的位置

位于**应用层和传输层之间**，对应用层透明：

```
应用层（HTTP、gRPC、FTP）
↓
TLS层（加密、解密）
↓
传输层（TCP）
↓
网络层（IP）
```

#### 2. TLS 1.2 完整握手过程（最常用）

用通俗的话解释，TLS 握手就是**双方协商出一个对称密钥**，然后用这个密钥加密后续的所有通信。

1. **客户端 Hello**：客户端发送支持的 TLS 版本、加密套件、随机数 C
2. **服务端 Hello**：服务端选择 TLS 版本、加密套件、随机数 S，发送自己的数字证书
3. **客户端验证证书**：客户端用 CA 的公钥验证证书的合法性，确保证书是服务端的
4. **客户端发送预主密钥**：客户端生成一个随机的预主密钥，用服务端的公钥加密后发给服务端
5. **双方计算会话密钥**：客户端和服务端用随机数 C、随机数 S、预主密钥，计算出相同的会话密钥（对称密钥）
6. **客户端发送加密完成消息**：用会话密钥加密一个 "Finished" 消息发给服务端
7. **服务端发送加密完成消息**：用会话密钥加密一个 "Finished" 消息发给客户端
8. **握手完成**：后续所有通信都用这个会话密钥加密

#### 3. TLS 1.3 的改进

- 握手从 2 次 RTT（往返时间）减少到 1 次 RTT，甚至 0 次 RTT
- 移除了所有不安全的加密算法
- 安全性更高，性能更好

#### 4. 证书体系

- **CA（证书颁发机构）**：可信的第三方机构，负责颁发和管理数字证书
- **数字证书**：包含服务端的公钥、域名、有效期等信息，由 CA 的私钥签名
- **证书链**：根 CA 证书 → 中间 CA 证书 → 服务端证书，逐级验证
