### 三者关系与对比
一、@Slf 4 j
① 角色：快捷工具；
② 核心作用：自动生成 Logger 实例，简化代码；
③ 典型使用方式：类上添加 @Slf 4 j，直接用 log.Info ()；

二、Logger
① 角色：操作接口；
② 核心作用：定义日志方法，提供操作能力；
③ 典型使用方式：调用 log.Info ("xxx")；

三、LoggerFactory
① 角色：实例工厂；
② 核心作用：创建 Logger 实例，关联实现；
③ 典型使用方式：Logger log = LoggerFactory.GetLogger (XXX. Class)；

四、代码示例:// ==DEBUG 级别，需要配置才能输出==
```java
# @Slf4j // 使用 SLF4J
public class PublisherTest {
  @Test
  public void testConfirmCallback() {
    log.info("进入 testConfirmCallback"); // INFO 级别，总会输出
    log.debug("收到 confirm callback 回执"); 
  }
}
```

| 维度        | Canal                          | ELK/EFK                        |
| :-------- | :----------------------------- | :----------------------------- |
| **核心定位**  | 数据库增量数据同步工具                    | 通用日志管理与分析平台                    |
| **唯一数据源** | MySQL binlog 日志                | 所有能输出文本的地方                     |
| **数据内容**  | 结构化的数据库变更事件（增删改）               | 非结构化 / 半结构化的日志文本               |
| **工作原理**  | 模拟 MySQL 从库，实时推送 binlog        | 客户端（Filebeat/Fluentd）拉取 / 推送日志 |
| **核心能力**  | 准实时、无丢失地捕获数据变更                 | 海量日志的检索、统计、可视化                 |
| **典型用途**  | 同步数据到 ES/Redis/Kafka、数据异构、缓存更新 | 问题排查、系统监控、业务指标统计               |
