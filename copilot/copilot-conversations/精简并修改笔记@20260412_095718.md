# 字节流与位流

## 概念
- 字节（Byte）= 8 位（bit）。
- 字节流：以字节为单位读写，字节对齐，适合文本与常见二进制格式。
- 位流：以位为单位读写，可跨字节边界，适合压缩和带有紧凑位域的协议。

## 核心区别
- 颗粒度：字节流按 8 位，位流可按任意位数（如 3、5 位）处理。
- 目的：字节流兼容性好；位流节省空间、适合可变长度编码。
- 实现复杂度：字节流简单；位流需管理缓冲、移位、掩码与位序。
- 性能：字节为主的硬件更高效；位流节省空间但增加 CPU 开销与随机访问难度。

## 常见应用
- 字节流：文本（UTF-8/ASCII）、PNG/ZIP、文件/库接口。
- 位流：霍夫曼/算术编码、音视频编码、紧凑协议与嵌入式帧格式。

## 位级操作要点
- 常用操作：移位（<<, >>, >>>）、掩码 (&)、位或 (|)、位非 (~)。
- 读写思路：
  - 写入：把待写位拼入缓冲，满 8 位写出一个字节，剩余位留缓存。
  - 读取：从流中补字节到缓冲，按需移位并掩码提取 n 位，保留剩余位。
- 注意位序（MSB-first vs LSB-first）与字节序（endianness）；两者不同且均需与规范一致。
- 填充规则需明确（如末尾填 0、填 1 或指定模式）。

## 伪代码（核心）
- 写入（BitOutputStream）
```
int buffer = 0, count = 0;
void writeBits(int v, int k) {
  buffer = (buffer << k) | (v & ((1 << k) - 1));
  count += k;
  while (count >= 8) {
    int out = (buffer >> (count - 8)) & 0xFF;
    outputStream.write(out);
    count -= 8;
  }
}
void flush() {
  if (count > 0) {
    outputStream.write((buffer << (8 - count)) & 0xFF);
    count = 0;
  }
}
```
- 读取（BitInputStream）
```
int buffer = 0, count = 0;
int readBits(int n) {
  while (count < n) {
    int b = inputStream.read();
    if (b < 0) throw EOFException;
    buffer = (buffer << 8) | b;
    count += 8;
  }
  int result = (buffer >> (count - n)) & ((1 << n) - 1);
  count -= n;
  buffer &= (1 << count) - 1;
  return result;
}
```

## 实践建议
- 优先选用字节流，只有在确需节省位级空间或协议要求时使用位流。
- 先定义格式（字段位长、位序、填充），写单元测试覆盖边界（跨字节、末尾未对齐等）。
- 优先复用成熟库（BitInputStream/OutputStream、BitSet、压缩库），避免重复实现。
- 在性能敏感场景做基准测试，权衡 CPU 与存储开销。

## 常见陷阱
- 混淆位序与字节序；填充不一致导致互操作失败；未处理写入剩余位导致数据丢失；EOF 与异常处理不当。
