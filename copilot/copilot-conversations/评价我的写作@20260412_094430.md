为什么 JDK 9 把 String 的 char[] 改成 byte[]？

概述
- Java 9 引入了“Compact Strings”：当字符串的所有字符都能用单字节 Latin‑1（ISO‑8859‑1）表示时，在内部用 byte[] 存储并通过一个 coder 字段记录编码；否则使用 UTF‑16 表示（每个 char 为 2 字节）[^1]。

实现要点
- 存储结构：原来的 private final char[] value 改为 private final byte[] value，增加 private final byte coder 用以标识当前实例的编码（LATIN1 或 UTF16）[^1]。
- coder 的取值（实现中）通常为：
  - LATIN1 = 0
  - UTF16 = 1
- 运行时策略：创建字符串时会检测内容是否全部适合 Latin‑1；若是则在 value 中按 Latin‑1 存单字节并把 coder 设为 LATIN1，否则以 UTF‑16 表示并把 coder 设为 UTF16。许多 String 方法会根据 isLatin1() 做分支调用不同实现（例如 indexOf）[^1]。

- 字段（JDK11 近似）：

  private final byte coder;
- 方法分支示例：

      return isLatin1() ? StringLatin1.indexOf(value, ch, fromIndex)
                        : StringUTF16.indexOf(value, ch, fromIndex);
  }
  private boolean isLatin1() { return COMPACT_STRINGS && coder == LATIN1; }[^1]

优点（为什么要这样做）
- 节省内存：对以 Latin‑1 字符为主（例如大量英文或西欧字符）的应用，单字节存储可将字符串内存占用接近减半，从而减少堆内存使用与 GC 压力，整体内存占比与 GC 行为可明显改善[^3]。
