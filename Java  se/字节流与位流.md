# 字节流与位流

## 概念
- 字节（Byte）= 8 位（bit）。
- ASCII 是最基础的字符编码：通常用 7 位表示一个字符，存储在 1 个字节中（最高位通常为 0）。
- 字节流（byte stream）：以完整字节为单位读写数据，数据在字节边界上对齐。
- 位流（bit stream）：以比特为最小单位读写数据，可跨越字节边界，常用于压缩或需精确位字段的协议/格式。

## 核心区别（要点）
- 颗粒度：字节流按字节（8 位）处理；位流按任意位（如 3、5 位），可能跨字节边界。
- 目的
  - 字节流：适合现有标准格式、文本、二进制文件等，易于解析与互操作。
  - 位流：适合压缩（如霍夫曼编码）、位域（bit-field）协议、音视频编码等，能提高空间利用率。
- 实现复杂度
  - 字节流：实现简单（InputStream/OutputStream）。
  - 位流：需手动缓存读写的剩余比特，涉及移位、掩码、对齐与位序（MSB/LSB）处理。
- 性能与空间
  - 字节流：随机访问与索引简单，高速（现代硬件以字节为单位）。
  - 位流：节省空间但增加 CPU 开销与实现复杂度；对随机访问不友好。

## 常见应用场景
- 使用字节流：
  - 文本文件（UTF-8/ASCII）、现成二进制格式（PNG、ZIP 等）、与库/系统接口交互。
- 使用位流：
  - 数据压缩（霍夫曼、算术编码）、网络协议中的紧凑位字段、某些嵌入式/通信帧格式、音视频编码。

## 常见操作（位级别）
- 基本位运算：左移（<<）、右移（>>/>>>）、位与 (&)、位或 (|)、位非 (~)。
- 常见技巧：
  - 读取 n 位：从缓冲字节中移位并掩码取出低 n 位或高 n 位，维护一个“剩余位”计数器。
  - 写入 n 位：将待写入的位拼接到缓冲寄存器，满 8 位则写出一个字节，剩余继续缓存。
- 注意位序（Bit order）：
  - 有些格式按 MSB-first（先高位），有些按 LSB-first（先低位）；实现时必须与格式规范一致。

## 示例（伪代码：位写入与读取）
- 写入（BitOutputStream 的核心思想）
  - 初始化 buffer = 0，count = 0
  - 写入 k 位的值 v：
    - buffer = (buffer << k) | (v & mask(k))
    - count += k
    - while count >= 8:
      - 输出 (buffer >> (count - 8)) & 0xFF
      - count -= 8
    - 保留剩余位在 buffer 中
- 读取（BitInputStream 的核心思想）
  - 初始化 buffer = 0，count = 0
  - 需要 n 位时：
    - while count < n:
      - buffer = (buffer << 8) | readByte()
      - count += 8
    - result = (buffer >> (count - n)) & mask(n)
    - count -= n
    - buffer &= mask(count)  // 保留剩余位

## 优点与代价
- 优点（位流）
  - 节省存储空间（尤其对不定长或频繁出现短编码的场景）。
  - 能实现精细的位级控制（紧凑协议/格式）。
- 代价（位流）
  - 实现复杂度高：需要管理缓冲、对齐与位序。
  - 性能开销：CPU 移位/掩码增加，随机访问困难。
  - 易出错：边界情况（剩余位、填充位）需谨慎处理。
- 字节流的优点是实现简单、兼容性好，缺点是空间利用不如位流精细。

## 常见陷阱与注意点
- 位序（MSB vs LSB）与字节序（endianness）要区分：位序决定位在字节内的先后，字节序决定多字节值在字节序列中的顺序。
- 填充（padding）：位流常需在末尾填充到字节边界，必须约定填充规则（填 0、填 1 或指定位模式）。
- IO 缓冲与异常：位流实现需对 IO 异常、流结束（EOF）处理慎重，避免丢失未写出的剩余位。
- 与现有库协作：优先考虑是否已有成熟库（如 Java 中常见的 BitSet、第三方 BitInputStream/OutputStream 实现）可用，别重复造轮子。

## 实践建议
- 优先用字节流，只有在确实需要节省位级空间或协议要求时才使用位流。
- 先定义格式规范（每个字段的位长、位序、填充规则），再实现读写逻辑并写单元测试覆盖边界情况（未对齐末尾、单字节字段、跨字节字段）。
- 编写工具函数封装常见操作（读 n 位、写 n 位、对齐到字节、刷出缓存）。
- 在性能敏感场景下做基准测试，权衡 CPU 开销与空间节省。
- 在笔记/文档中记录位序与填充约定，便于后续维护与互操作。

## 简要示例（Java 风格伪代码）
- 写 5 位值到输出流（伪代码）
```
int buffer = 0;
int count = 0; // 当前 buffer 中的位数
void writeBits(int v, int k) {
  buffer = (buffer << k) | (v & ((1 << k) - 1));
  count += k;
  while (count >= 8) {
    int out = (buffer >> (count - 8)) & 0xFF;
    outputStream.write(out);
    count -= 8;
  }
}
void flush() {
  if (count > 0) {
    outputStream.write((buffer << (8 - count)) & 0xFF); // 填充到字节边界
    count = 0;
  }
}
```

## 参考/延伸
- 霍夫曼编码（Huffman）：典型的位流应用，编码长度可变，常需按位打包输出。
- 常见文件格式：PNG、JPEG、MP3 等在某些环节使用位级编码或位域。
- 查阅现成实现：搜索 BitInputStream/BitOutputStream、BitSet，以及相关压缩库（zlib、lz4 等）以借鉴实现细节。

### 1 字节（Byte）= 8 位（bit）：ASCII 编码（基础编码）

	规则：1 个字符 = 1 个字节（8 位）（实际仅用 7 位存储有效数据，最高位为 0）。

举例：字符 `'a'`、`'5'`、`'!'` 在 ASCII 编码下，都只占用 1 个字节（8 位）。

| 对比维度   | Word 文档读取（字节流）         | 霍夫曼压缩（位流）                   |
| ------ | ---------------------- | --------------------------- |
| 核心目标   | 正确解析已有标准格式，获取文档内容      | 最小化存储空间，实现极致压缩比             |
| 数据形态   | 完整字节序列（已字节对齐，无零散位）     | 大量零散位编码（5 位、3 位等，非字节对齐）     |
| 流的选择依据 | 符合计算机字节存储规则，有成熟库支持解析   | 突破字节边界，消除填充浪费，最大化空间利用率      |
| 核心操作   | 调用 POI 库，按字节读取、解析预定义格式 | 手动实现位级操作（移位、位与、位或），拼接 / 拆分位 |
| 通俗类比   | 拆快递：打开现成的标准包装盒，取出内部物品  | 打包快递：将零散小物件紧凑拼接，凑够箱子再封装     |
