# 分布式、RPC、Feign 三者的关系

**分布式是业务架构，RPC 是跨服务调用的核心思想，Feign 是 RPC 思想的一种具体实现工具**

---
## 一、概念
### 1. 常见的分布式有哪些功能板块？
	举个例子：一个电商系统，拆成
	「用户服务」管登录注册、
	「订单服务」管下单支付、
	「商品服务」管商品库存，
三个服务分开跑，订单服务要查用户信息，就得调用用户服务，这就是最典型的分布式场景。

## 分布式设计原理
分布式架构的核心目标是**服务解耦、独立部署、水平扩展**，解决单体应用迭代慢、性能瓶颈、维护成本高的问题，你之前说的「解耦」，就是分布式最核心的出发点。

---

## 2. 什么是 RPC？
#### 大白话定义
**RPC = Remote Procedure Call = 远程过程调用**，它不是一个具体的工具/框架，而是一套**标准化的思想/规范**。
这套思想的核心只有一件事：**让你调用另一台服务器上的方法，和调用你本地项目里的方法，写法、体验完全一模一样，完全感知不到是跨机器、跨服务调用**。

例子：
你在本地写代码，调用一个方法：
```java
// 你以为这是本地方法，直接调用就能拿到结果
UserDTO user = userService.getUserById(1L);
```
正常来说，这个 `userService` 的代码就在你当前的项目里，方法在你本地服务器跑。
但如果用了 RPC，这个 `userService` 的真实代码，其实在另一台服务器的「用户服务」里，你在「订单服务」里写这句代码，**完全不用改任何写法**，就能直接拿到结果。
背后的网络请求、IP 地址查找、参数打包、结果解析这些复杂的底层细节，全给你屏蔽了，你只管写业务代码就行。

#### RPC 调用，6 步流程
一个完整的 RPC 调用，底层固定 6 步流程（小白只需要知道有这回事就行）：
1. 客户端（调用方，比如订单服务）调用本地定义的接口方法

2. RPC 框架把方法名、参数、调用信息打包（序列化）
3. 通过网络协议（TCP/HTTP 等）把数据包发给服务端（被调用方，比如用户服务）


4. 服务端 RPC 框架收到包，解析数据（反序列化），找到对应的真实方法执行
5. 把执行结果打包，通过网络发回给客户端
6. 客户端 RPC 框架解析结果，返回给你的业务代码

## 3. Feign 和 RPC 到底是什么关系？

**Feign（包括 Spring Cloud 里的 OpenFeign），是 Spring 生态里最常用的 RPC 工具之一**

你之前写的 Feign 代码，完全就是 RPC 的标准用法：
```java
// 定义Feign接口，告诉Spring这个接口要调用远程的user-service服务
@FeignClient(name = "user-service")
public interface UserClient {
    @GetMapping("/user/{id}")
    UserDTO getUser(@PathVariable Long id);
}

// 业务代码里直接调用，和调用本地方法一模一样
UserDTO user = userClient.getUser(1L);
```
符合 RPC 的核心：
- 你不用手写 HTTP 请求、不用管对方服务的 IP 端口、不用拼接参数、不用解析返回结果
- 完全屏蔽了远程调用的底层细节，实现了「像调用本地方法一样调用远程服务」
- 底层的序列化、网络请求、服务地址查找、结果反序列化，全是 Feign 帮你做了

#### Feign 和其他 RPC 框架的区别

|RPC 框架|底层协议|核心优势|适用场景|
|---|---|---|---|
|Feign/OpenFeign|HTTP/1.1|写法贴合 Spring MVC，零门槛上手，和 Spring 生态无缝兼容|Spring Cloud 微服务项目，绝大多数业务场景|
|Dubbo|自定义 TCP 协议（默认）|性能更高、延迟更低|高并发、低延迟要求的微服务场景|
|gRPC|HTTP/2|跨语言能力强，序列化效率高|多语言开发的分布式系统|
