# 分布式是跨服务，首先就是拦截，拦截里面去拿东西
	所以一定要定义好一个 Handler 拦截器
	
不管是哪种 RPC 框架，都会提供拦截器/过滤器机制，用来实现分布式场景下的全链路能力，完整的链路逻辑是这样的：
1. **入站拦截（请求进入你的服务）**：用 Spring MVC 的 `HandlerInterceptor`（就是你说的 Handler 拦截器），从 HTTP 请求头里取出 traceId、用户 token、userId 这些公共数据，放进 `ThreadLocal` 里，给整个业务链路复用
2. **业务代码执行**：全程不用手动传这些公共数据，直接从 `ThreadLocal` 里取
3. **出站拦截（你调用其他远程服务）**：用 Feign 自带的 `RequestInterceptor`（Dubbo 用 Filter 拦截器），从 `ThreadLocal` 里取出这些公共数据，自动塞进新的请求头里，传给下一个服务
4. **请求结束清理**：拦截器里清理 `ThreadLocal`，避免内存泄漏
这套逻辑，就是分布式系统里**全链路追踪、权限统一校验、日志上下文透传**的标准实现方案，


专业补全
一个完整的 RPC 调用，底层固定 6 步流程（小白只需要知道有这回事就行）：
1. 客户端（调用方，比如订单服务）调用本地定义的接口方法

2. RPC 框架把方法名、参数、调用信息打包（序列化）
3. 通过网络协议（TCP/HTTP 等）把数据包发给服务端（被调用方，比如用户服务）


4. 服务端 RPC 框架收到包，解析数据（反序列化），找到对应的真实方法执行
5. 把执行结果打包，通过网络发回给客户端
6. 客户端 RPC 框架解析结果，返回给你的业务代码
