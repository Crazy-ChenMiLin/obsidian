#### L 1 本地缓存 Caffeine

Key 格式：`feed:public:{size}:{page}:v1`

- 先查本机内存缓存
- 命中：直接返回数据，速度最快
- 未命中：往下走 L 2

#### L 2 Redis 片段缓存

拆成两部分存：

- 动态 ID 列表：`feed:public:ids:{size}:{hourSlot}:{page}`
- 单条动态详情：`feed:item:{id}`
- 还有 hasMore 有没有下一页标记
- 命中：组装数据直接返回
- 未命中：往下走 L 3 回源 DB





流程问题：

==不该数据库，只动缓存和 redis 缓存==

==Linkedhashset 不存热点 key 而是 feed 的 key，防止重复==

- 监听点赞 / 收藏事件 → 拿到**知文 ID**
- 查一下这篇知文的作者 → 更新作者的总点赞 / 收藏计数（Redis 计数）
- **核心：去 Redis 查反向索引** → 找到所有包含这篇知文的 Feed 页面 key
    
    - 查**当前小时**的索引
    - 查**上一小时**的索引
    - 把所有 key 放进 `LinkedHashSet` 里
    
- 遍历这些 key，**先更新本地缓存 (Caffeine)**，**再更新 Redis 缓存**
- 更新方式：把缓存数据转成对象 → 改数字 → 写回缓存
