| 序号  | 数据类型                    | 核心特性                                                                        | 底层实现结构（含版本说明）                                                                                                                                         | 核心操作时间复杂度                                                                                    | 最优适配缓存 / 业务场景                                                                                                 | 不推荐使用的场景                                                                                  |

| 01  | String（字符串）             | Redis 最基础的通用类型，二进制安全，支持字符串、整数、浮点数，最大存储 512MB                                | 核心底层为**SDS（简单动态字符串）**；值为整数且在 long 范围内时用 int 编码；短字符串用 embstr 编码，长字符串用 raw 编码                                                                           | 核心读写 GET/SET：O (1)<br><br>计数 INCR/DECR：O (1)                                                 | 1. 单值缓存：用户 Token、短信验证码、接口幂等键<br><br>2. 数值计数：文章阅读量、商品库存<br><br>3. 分布式锁、位图操作、简单的静态数据 JSON 缓存                    | 1. 高频单元素增删、需要去重的列表类数据（如点赞列表）<br><br>2. 大体积 JSON（超过 10KB），无法字段级独立更新<br><br>3. 需要聚合运算的集合类数据 |
| 02  | List（列表）                | 双向有序的字符串元素集合，元素可重复，支持首尾快速增删，支持按索引下标访问                                       | Redis 3.2+ 统一使用**quicklist（快速列表）**；quicklist 是由多个 listpack（7.0+）/ziplist（旧版本）组成的双向链表，兼顾内存占用与读写性能                                                      | 首尾增删 LPUSH/RPOP：O (1)<br><br>按索引查询 / 修改：O (N)<br><br>范围查询 LRANGE：O (M)，M 为返回元素数量             | 1. 消息队列、任务队列（轻量级场景）<br><br>2. 用户消息通知、Feed 流 timeline<br><br>3. 关注列表、历史浏览记录等有序可重复列表                            | 1. 需要随机读写、频繁按中间索引修改的场景<br><br>2. 需要去重的集合场景<br><br>3. 百万级海量数据存储，范围查询性能会急剧下降                |
| 03  | Hash（哈希）                | 键值对集合，一个 key 对应多个 field-value，支持字段级独立读写，无需全量操作，天然适配结构化对象                    | 初始实现：**ziplist（压缩列表）、hashtable（哈希表）**；<br><br>Redis 7.0+ 用**listpack（紧凑列表）** 完全替代 ziplist；字段少、值体积小时用 listpack/ziplist，不满足条件自动转为 hashtable             | 字段读写 HSET/HGET：O (1)<br><br>全量获取 HGETALL：O (N)，N 为字段总数                                       | 1. 结构化对象缓存：用户信息、商品多规格属性、系统配置项<br><br>2. 需要频繁更新单个字段、无需全量序列化的场景<br><br>3. 购物车、用户权限字段管理                          | 1. 无结构化的单值数据（不如 String 简洁）<br><br>2. 海量成员的去重集合场景<br><br>3. 需要跨 key 集合运算、排序的场景             |
| 04  | Set（集合）                 | 无序、不可重复的字符串元素集合，原生支持集合间交集、并集、差集运算，单元素操作性能极强                                 | 初始实现：**intset（整数集合）、hashtable（哈希表）**；<br><br>所有成员均为整数且数量不超过阈值（默认 512）时用 intset，不满足条件自动转为 hashtable                                                    | 单元素增删 / 存在判断 SADD/SREM/SISMEMBER：O (1)<br><br>集合交 / 并 / 差集：O (N)，N 为参与运算的元素总数                | 1. 去重类场景：文章点赞 / 收藏、用户关注 / 粉丝、黑白名单<br><br>2. 标签体系、用户兴趣圈、共同关注 / 共同好友计算<br><br>3. 随机抽奖、活动参与人员去重                  | 1. 需要有序排序、按权重筛选的场景<br><br>2. 需要按索引访问的列表场景<br><br>3. 单 key 单值的简单缓存场景                       |
| 05  | ZSet（有序集合 / Sorted Set） | 不可重复的字符串元素集合，每个元素绑定一个 double 类型的 score（分数），Redis 按 score 自动全局排序，支持排名、分数范围查询 | 初始实现：**ziplist（压缩列表）、skiplist（跳表）+ hashtable（哈希表）**；<br><br>Redis 7.0+ 用**listpack（紧凑列表）** 替代 ziplist；元素少、值体积小时用 listpack/ziplist，不满足条件转为跳表 + 哈希表组合结构 | 单元素增删改 ZADD/ZREM：O (logN)<br><br>排名 / 分数范围查询：O (logN + M)，M 为返回元素数量<br><br>成员排名 / 分数查询：O (1) | 1. 实时排行榜：游戏积分榜、商品销量榜、内容热度榜<br><br>2. 延时队列、定时任务调度<br><br>3. 滑动窗口限流、接口流量控制<br><br>4. 带权重的用户标签、优先级任务调度、精细化数据范围筛选 | 1. 无排序需求的简单去重场景（不如 Set 节省资源）<br><br>2. 无结构化的单值数据<br><br>3. 频繁全量遍历的场景，性能不如 Hash/Set        |
