# 1. 比较操作符

| 操作符         | 说明             | 小白示例                         | 避坑 & 注意                                             |
| ----------- | -------------- | ---------------------------- | --------------------------------------------------- |
| `=`         | 等于             | `WHERE id = 101`（经理题）        | 字符串必须加单引号`'Y'`，漏写会被当成列名报错                           |
| `<>` / `!=` | 不等于            | `WHERE low_fats <> 'Y'`（产品题） | 两者完全等价，`!=`可读性更强，更通用                                |
| `<`         | 小于             | `WHERE score < 60`           | 支持数字、日期、字符串（按字典序比较）                                 |
| `<=`        | 小于等于           | `WHERE score <= 60`          | 闭区间，包含等于的边界值                                        |
| `>`         | 大于             | `WHERE score > 90`           | 同上                                                  |
| `>=`        | 大于等于           | `WHERE score >= 90`          | 同上                                                  |
| `!<`        | 不小于（等价于`>=`）   | `WHERE score !< 60`          | 不常用，建议直接用`>=`，避免可读性问题                               |
| `!>`        | 不大于（等价于`<=`）   | `WHERE score !> 60`          | 不常用，建议直接用`<=`                                       |
| `<=>`       | 安全等于（MySQL 专属） | `WHERE managerId <=> NULL`   | 解决 NULL 比较问题：`NULL <=> NULL`为真，`5 <=> NULL`为假，进阶场景用 |
# 2. 范围 / 集合操作符

| 操作符                   | 说明                 | 小白示例                                | 避坑 & 注意                                                 |
| --------------------- | ------------------ | ----------------------------------- | ------------------------------------------------------- |
| `BETWEEN ... AND ...` | 闭区间范围匹配（包含两端）      | `WHERE score BETWEEN 60 AND 90`     | 等价于`score >=60 AND score <=90`，**必须左小右大**，写反会查不到数据；支持日期 |
| `IN (值1,值2,...)`      | 多值等于匹配（`OR`的语法糖）   | `WHERE id IN (101,102,103)`（经理题子查询） | 集合元素**严禁出现 NULL**，否则`NOT IN`会返回空；支持子查询作为集合              |
| `NOT IN (值1,值2,...)`  | 不在指定集合内            | `WHERE id NOT IN (101,102,103)`     | 同上，**集合含 NULL 时结果全为空**，是小白最高频踩坑点                        |
| `ANY` / `SOME`        | 匹配集合中任意一个（等价于`IN`） | `WHERE score > ANY (80,90,95)`      | 等价于`score>80 OR score>90 OR score>95`，不常用，建议直接用`IN`     |
| `ALL`                 | 匹配集合中所有            | `WHERE score > ALL (80,90,95)`      | 等价于`score>95`，用于多值比较，面试偶尔考察                             |

# 3. 空值判断操作符 

| 操作符           | 说明                | 小白示例                               | 避坑 & 注意                                                              |
| ------------- | ----------------- | ---------------------------------- | -------------------------------------------------------------------- |
| `IS NULL`     | 判断字段为 NULL        | `WHERE managerId IS NULL`（经理题）     | **绝对不能用`= NULL`**！NULL 和任何值比较都为 NULL，`WHERE managerId = NULL`永远查不到数据 |
| `IS NOT NULL` | 判断字段不为 NULL       | `WHERE managerId IS NOT NULL`（经理题） | 同上，不能用`!= NULL`                                                      |
| `ISNULL(字段)`  | MySQL 函数，判断为 NULL | `WHERE ISNULL(managerId)`          | 等价于`IS NULL`，函数写法，部分复杂场景更灵活                                          |
| `<=>`         | 安全等于（复用上面）        | `WHERE managerId <=> NULL`         | 唯一能正确判断 NULL 相等的操作符，解决`= NULL`的坑                                     |
✅ 判断空值 → 只能用 `IS NULL`

# 6. 存在性判断操作符
| 操作符          | 说明           | 小白示例                                                                                                                                              | 避坑 & 注意                                          |
| ------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `EXISTS`     | 子查询返回结果则条件为真 | `sql SELECT name FROM Employee e1 WHERE EXISTS ( SELECT 1 FROM Employee e2 WHERE e2.managerId = e1.id GROUP BY e2.managerId HAVING COUNT(*)>=5 )` | 子查询只判断「是否有结果」，不返回数据，**大集合时性能远优于 `IN`**，不会踩 NULL 坑 |
| `NOT EXISTS` | 子查询无结果则条件为真  | `SELECT name FROM Employee WHERE NOT EXISTS (SELECT 1 FROM Employee WHERE managerId = Employee.id)`                                               | 找「没有下属的经理」，等价于 `LEFT JOIN + IS NULL`，性能更优         |

# 4. 模糊匹配操作符

| 操作符                | 说明                | 小白示例                           | 避坑 & 注意                                            |     |
| ------------------ | ----------------- | ------------------------------ | -------------------------------------------------- | --- |
| `LIKE`             | 模糊匹配（通配符）         | `WHERE name LIKE '张%'`         | `%`匹配任意多个字符（含 0 个），`_`匹配单个字符；**左 % 会导致索引失效**，是性能大坑 |     |
| `NOT LIKE`         | 不匹配模糊规则           | `WHERE name NOT LIKE '张%'`     | 同上                                                 |     |
| `REGEXP` / `RLIKE` | 正则表达式匹配（MySQL 专属） | `WHERE name REGEXP '^张[三李四]$'` | 支持复杂正则匹配，性能比`LIKE`差，非必要不使用                         |     |

# 7. 去重关键字（DISTINCT）

| 操作符 / 关键字  | 说明          | 小白示例                                                                                                            | 避坑 & 注意                                                                                                                                                                                                                                                                                                                                        |
| ---------- | ----------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DISTINCT` | 去除查询结果中的重复行 | `SELECT DISTINCT department FROM Employee;`（查所有不重复的部门）<br><br>`SELECT DISTINCT id, name FROM Employee;`（多列组合去重） | 1. `DISTINCT` 作用于**所有选中的列**（如 `SELECT DISTINCT a,b` 是按 a+b 组合去重，非仅去重 a）；<br><br>2. 对 NULL：多个 NULL 会被视为重复，仅保留一个；<br><br>3. 性能：大数据量下会触发排序，纯去重场景可替换为 `GROUP BY`（如 `SELECT dept FROM emp GROUP BY dept`），性能更优；<br><br>4. 可与聚合函数联用：`SELECT DISTINCT COUNT(id) FROM emp` → 先去重再计数（需注意逻辑）；<br><br>5. 与 `ALL`（默认）相对：不写 `DISTINCT` 等价于 `ALL`（返回所有行，含重复） |
| ALL        | 不去重         |                                                                                                                 |                                                                                                                                                                                                                                                                                                                                                |

# 8.分页查询

|用法类型|语法示例|作用|典型场景|
|---|---|---|---|
|纯限制数量|`LIMIT 10`|取前 10 行，从行 0 开始|查最新 / 最贵的 Top N 条数据|
|分页查询|`LIMIT 10 OFFSET 0`|第 1 页，每页 10 条（取前 10 行）|商品列表分页第 1 页|
|分页查询|`LIMIT 10 OFFSET 10`|第 2 页，每页 10 条（跳过前 10 行，取 10 行）|商品列表分页第 2 页|
|分页查询|`LIMIT 10 OFFSET 20`|第 3 页，每页 10 条（跳过前 20 行，取 10 行）|商品列表分页第 3 页|
